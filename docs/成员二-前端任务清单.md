## 二、任务清单

### P0-1　对话页 `#chat`（0.5 天）

**目标**：评委说一句话，就能跑完「定位天窗 → 出冲突 → 出方案」。

**页面结构**

```
┌───────────────────────────────────────────────┐
│  说什么都行：核查 9 月 23 号 07:30 那个天窗    │  ← 输入框 + 发送
├───────────────────────────────────────────────┤
│  你：核查 9 月 23 号 07:30 那个天窗            │
│                                               │
│  AI：我理解你要查 2026-09-23 07:30—09:20，     │  ← echo（可点"不对"重问）
│      12 条作业，正在按编制预审跑。             │
│                                               │
│  ┌ 方案 A｜检查工区顺延 ─┐ ┌ 方案 B｜保留全部 ┐ │  ← 复用确认台的结果卡
│  │ 冲突 0 · 延期 6 条     │ │ 冲突 10 · 严重 6 │ │
│  └───────────────────────┘ └─────────────────┘ │
│  建议：方案 A（安全优先）　退路：改取 B 并划界点 │
└───────────────────────────────────────────────┘
```

**四种终态，前端只认 `status`**

| status | 页面表现 |
|---|---|
| `tool_call` | 显示「正在检索天窗…」（后端在跑第二轮，用户看不到工具） |
| `ok` | 显示 `echo` + 结果卡（方案/冲突/建议） |
| `need_choice` | 列出 `candidates`，点一个继续（带上 windowId 重新提问） |
| `not_found` / `error` | 显示 `reply`，并提供「手动选天窗」的兜底入口 |

**验收**

- [ ] 输入「核查 9 月 23 号 07:30 那个天窗」→ 出 A/B 两套方案 + 建议
- [ ] 输入「核查 9 月 23 号那个天窗」（同一天 5 个窗口）→ 列出候选，点一个能继续
- [ ] 输入「今天天气」→ 显示 `not_found` 文案，不崩
- [ ] 接口指向不存在的地址 → 显示降级提示，其余页面不受影响
- [ ] 输入框回车即发送；请求中禁点，避免重复调用

## 三、接口契约（照 `架构-对话入口-v1.md` 第五节）

```json
// 请求
{ "text": "核查 9 月 23 号 07:30 那个天窗" }

// 命中
{ "status": "ok",
  "echo": "2026-09-23 07:30—09:20，12 条作业",
  "command": { "windowId": 2, "taskMode": "PRE_REVIEW" },
  "reply": "…",
  "result": { "verdict": {...}, "plans": [...], "conflicts": [...] } }

// 歧义
{ "status": "need_choice",
  "candidates": [ {"windowId": 2, "label": "2026-09-23 07:30—09:20，12 条作业"} ] }
```
